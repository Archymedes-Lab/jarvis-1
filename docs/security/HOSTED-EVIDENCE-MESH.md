# Hosted evidence witness and continuous publisher

## Invariants recorded before editing (2026-10-02)

- Only the existing allowlisted pseudonymous process projection, source commitments and bounded encrypted status leave the origin. The origin archive key never leaves this host. Provider IP/timing/volume and stable stream keys remain privacy limitations; this is not full anonymity.
- A dedicated Cloudflare witness-signing key is a provider secret, never an origin key. Authentication precedes creation/routing of a Durable Object. Requests remain producer-signed, responses witness-signed and challenge-bound; clients pin the independently generated witness key, not a key supplied by an HTTP response.
- Each stream has transactional contiguous append-only storage, replay-safe duplicate handling and explicit capacity refusal. No remote delete/reset endpoint, TTL, automatic pruning or source-cursor mutation. Receipts are emitted only after durable storage synchronization.
- The continuous publisher uses an isolated origin/store and single-writer process lock. A new encrypted baseline records the current canonical cursor and its commitment plus the unreplicated historical prefix. This prevents a history backlog from hiding today's observations and never invents historical coverage.
- Source corruption, source rollback, peer rollback/forks, invalid/stale signatures, request interruption and exhausted retry/quota limits remain explicit failures. Publishing failures cannot stop or authorize collector/protection actions.
- A cycle is bounded: at most four batches, one configured hosted peer, 30-second minimum duty interval, existing per-batch source and wire bounds, two bounded transport attempts, atomic owner-only state receipt, no raw evidence or secret logs. Quiet periods receive fresh head challenges and an encrypted heartbeat at most every five minutes; receipt freshness is not sensor completeness.
- Supervision belongs to a separate restricted user service running a narrow sealed copy, with a restart policy and retained prior release. No protected JARVIS service cutover, power-policy change, account privilege change or credential-policy change is implied. Host sleep, Windows/WSL shutdown, network outages and sign-out remain explicit availability limits.
- A remote account administrator or attacker with account-management credentials can still delete/replace this deployment and its storage. Independent witnesses, account MFA/separation, retained checkpoints and separately protected recovery keys remain necessary for stronger assurance. No administrator-proof WORM claim.

## Design comparison

| Alternative | Integrity/durability | Operator/resource cost |
|---|---|---|
| Cloudflare Worker plus SQLite Durable Object | Serialized per-stream transactions and durable receipt gate, built-in persistent store; existing mesh protocol | One provider and small Worker, bounded requests/storage; account administrators remain authoritative |
| Vercel Functions plus Blob/database | Needs external atomic coordination and durable storage; ephemeral function files cannot be authority | Additional storage/account/service and failure contracts |
| Both providers immediately | Better administrative diversity only with independently operated copies | Twice the deployment/keys/storage paths before the first path is measured |

Select Cloudflare first. Add a second provider when the first path is measured and the independent store/coordination and account boundaries are concrete. Reconsider when measured ingestion latency, daily request/write allocation, storage growth or user-service availability exceeds the bounds.

Provider references: [SQLite Durable Objects transactions and synchronization](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/), [limits](https://developers.cloudflare.com/durable-objects/platform/limits/), [pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/), [Web Crypto Ed25519](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/), [Vercel Function limits](https://vercel.com/docs/functions/limitations). Cloudflare R2 bucket locks can be removed by account-authorized administrators; they are not an administrator-proof retention guarantee ([R2 documentation](https://developers.cloudflare.com/r2/buckets/bucket-locks/)).

## Operation after explicit credential-export approval

Provision only `WITNESS_SIGNING_PKCS8` using the owner-only ignored secret JSON; never print its value or pass it as a shell argument. Validate the returned signed head against the independently generated local witness pin. Install the prepared **new** user unit using exclusive creation after checking that its name is absent; run user daemon reload and enable/start only `jarvis-evidence-publisher.service`. The existing protected collector release is separate.

The first successful cycle declares pre-baseline history unreplicated. Examine owner-only `cloud-origin/publisher-state.json` for current `ok`, timestamp, source backlog and fresh witness count; use signed peer challenges and checkpoint recovery as independent gates. Do not treat a running process, a health endpoint, or a saved historical receipt as current custody. Verify at least two advancing cycles, controlled publisher restart and cloud retrieval/decryption against a saved checkpoint before advertising live replication.

A matching fresh head verifies availability of that head only. It does not prove every historical block is still stored; historical retrieval and full checkpoint recovery are separate checks. End-to-end cloud latency, Durable Object CPU allocation, live publisher CPU/RSS and recovery throughput cannot be measured until signing is provisioned. The staged publisher release occupies 140 KiB on disk; this is release disk usage, not live evidence growth or memory consumption.

The local ledger has a 256 MiB SQLite page budget including receipts and database overhead; the cloud has a 256 MiB accounted block-byte budget with SQLite/provider overhead additional. Capacity is a refusal, never pruning. Actual daily growth/request volume and provider allocation must be measured before claiming sustainable operation; quota/account limits can halt writes. Checkpoints and origin decryption keys need independently protected backups. Stop/disable only the publisher to roll back continuous publication; retain its local evidence, old releases and provider data.
